FreeSnitch 1.3 makes Insights something you can act on: you see what the firewall actually did with each connection, and you can turn any destination into a rule right there. If you use FreeSnitch 1.1.0 or newer, it updates itself. Coming from 1.0.0 or older, download the disk image once and replace the old copy; your rules and settings stay.

## New

- **New Rule… from Insights (#446).** Select a destination on the Apps tab and choose New Rule… (in the footer or the right-click menu). It opens the same Add Rule sheet as the Rules page, already filled in with the app and the host name, or the address when no name was seen. On the No Name tab you can make a rule for one app or for any app. Nothing is added until you press Add.
- **Allowed or Blocked in Insights (#447).** Every destination now says what happened to its connections: Allowed, Blocked, "120 of 340 blocked", Not filtered (let through without a rule decision, like local traffic or an unanswered alert) or Not blocked. Hover the label for the exact split. Apps that had anything blocked show "N blocked" in the list. Connections recorded before this update aren't counted, so older rows may show no label. A connection that waits on an alert now appears in Insights once you answer it.

## Fixes

- **Insights and the menu bar show the mode that's really enforced (#452).** If the app couldn't fetch the full rule set from the helper, it fell back to showing Silent Allow, even while Alert or Silent Deny was active. It now shows the mode the helper reports and keeps fetching until it has the current rules. Changing the mode with `freesnitch mode` also updates the Profiles page right away.

Requires macOS 13 or later. One universal build for Apple Silicon and Intel, signed with a Developer ID and notarized by Apple.
