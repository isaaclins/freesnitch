# FreeSnitch 0.4.1

## Repair Helper now repairs

After an automatic update, the app would notice that the privileged helper was still running the previous build, say so clearly, and then tell you to open Terminal and run a `sudo` command. Meanwhile the network extension had no helper to talk to, so **traffic was not being filtered** until you did it by hand.

A button called Repair Helper has to actually repair. It now restarts the helper for you, and macOS asks you to authorize it the normal way. If you dismiss that prompt nothing happens and the banner stays, which is how declining should work.

The action is deliberately narrow: it restarts the existing service and never unregisters it. Unregistering an enabled helper can remove the service outright, which is exactly why this was left manual before. Your approval in System Settings is untouched.

If the restart genuinely cannot be carried out, the command is still shown, as a fallback rather than as the plan.
